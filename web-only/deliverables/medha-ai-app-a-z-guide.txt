MEDHA AI COGNITIVE CARE
COMPLETE A-Z APP WORKING GUIDE
============================================================

Document status: Current MVP implementation guide
Prepared: 03 September 2026

IMPORTANT STATUS
----------------
Medha AI is currently a functional patient-facing MVP and testing
application. It is not yet a production medical, emergency-response,
or unattended-care system.

The current build uses local device storage for patient data and has
an Express API server for Gemini voice transcription. Supabase sync,
authentication, a caregiver web portal, remote alerts, SMS escalation,
and full background safety monitoring are not connected in this version.


A - ACCESSIBILITY
-----------------
The interface is designed for elderly users:

- Large readable headings and high-contrast controls.
- Calm navy, emerald, cream, peach, and sunlight color palette.
- Large touch targets and simple labels.
- No timer in the memory game.
- Voice prompts and higher-contrast settings are available in More.
- The microphone button can be moved to the easiest corner of the screen.

The current settings include:

- English
- Assamese
- Hindi
- Voice prompts on/off
- Higher contrast on/off
- Microphone position:
  bottom-left, bottom-right, top-left, or top-right


B - BACKEND
-----------
The backend is an Express 5 API located at:

    artifacts/api-server

The API is mounted below:

    /api

Current endpoints:

    GET  /api/healthz
    POST /api/voice/transcribe

The voice endpoint accepts:

    {
      "audioBase64": "base64 audio data",
      "mimeType": "audio/m4a",
      "languageHint": "Assamese, Hindi, or English"
    }

The server validates the request, limits inline audio to approximately
8 MB, sends the audio to Gemini, and returns:

    {
      "transcript": "spoken text",
      "language": "detected language",
      "possibleTask": {
        "title": "task title",
        "time": "task time",
        "recurrence": "task recurrence"
      }
    }

possibleTask is null when no clear reminder or future task is found.


C - CARE PLAN
------------
The Home screen shows the daily care plan:

- Morning medicine
- Hydration
- Morning walk
- Family doctor appointment

Each task has:

- A time
- A category
- A familiar icon
- Complete action
- Snooze action

Task state is persisted locally on the phone.

Tasks created from Voice Diary are shown for confirmation before they are
added to the care plan.


D - DATA STORAGE
----------------
The current mobile app stores its local state with AsyncStorage.

Stored local information includes:

- Patient profile
- Daily tasks
- Notifications
- Voice diary transcripts
- Local audio file references
- Game progress
- App settings
- Test-data status

The local storage key is:

    @medha-ai/app-state

This is device-local storage. It is not yet a shared patient database.
Clearing app data or uninstalling the application may remove this data.


E - EMERGENCY AND SOS
---------------------
The Safety screen is available from:

    Home -> Where am I? Help
    More -> SOS Mode

Current SOS flow:

1. Patient opens the safety screen.
2. Patient taps "Where am I? Help".
3. The app displays a calm reassurance screen.
4. A Good Samaritan can tap "Show this screen for help".
5. The app displays the patient's name, age, languages, home address,
   and caregiver call action.
6. The caregiver can be called with the phone's native phone app.
7. The patient can tap "I am safe now" to close SOS mode.

Current limitations:

- Remote caregiver notification is not connected.
- SMS fallback is not connected.
- Automatic fall or inactivity detection is not connected.
- Background geofence escalation is not production-ready.

Do not rely on this MVP as the only emergency response system.

G - GAMES
---------
The Games tab contains a functional memory-pair game called:

    Find the pairs

How it works:

1. Tap a hidden card.
2. Tap a second hidden card.
3. Matching cards stay open.
4. Non-matching cards close after a short pause.
5. The game ends when all pairs are found.
6. A score is calculated from the number of mistakes.

The game has no countdown timer. Sessions, last score, and best score are
stored locally.


H - HOME
--------
Home is the main patient entry point.

It contains:

- Date and greeting
- Test-data warning when the fake profile is active
- Daily rhythm and streak display
- Care-plan tasks
- Notification indicator
- Gentle note from the diary or default guidance
- Safety entry point
- Persistent microphone button

The current greeting uses the active local patient profile.


I - INSTALLATION
----------------
For development in the development workspace:

1. Install dependencies:

       pnpm install

2. Start the Expo mobile workflow:

       pnpm --filter @workspace/medha-ai run dev

3. Start the API workflow separately:

       pnpm --filter @workspace/api-server run dev

4. Open the Expo preview or scan the Expo QR code with Expo Go.

For an Android APK:

- A native Expo/EAS build is required.
- The production API URL must be configured in the build.
- The API server must be deployed and reachable by the phone.
- Android microphone, location, notification, and background permissions
  must be accepted and tested on a real device.


J - JOURNEY THROUGH THE APP
---------------------------
Typical patient journey:

1. Open Home.
2. Read the day's care plan.
3. Complete or snooze a task.
4. Open Games for memory practice.
5. Open Voice Diary and record a note.
6. Wait for Gemini transcription when online.
7. Review any possible reminder.
8. Tap Add only after confirming the reminder.
9. Open Memory Assistant for familiar people, places, and routines.
10. Use Safety/SOS when help is needed.
11. Use More for settings, alarms, reports, and test-data management.

N - NOTIFICATIONS
-----------------
The app includes local notification support through expo-notifications.

The Notifications & alarms setting:

- Requests notification permission on supported mobile devices.

The current reminder preview is a test action. Production repeating

O - OFFLINE BEHAVIOR
--------------------
The first mobile build is offline-first for local patient use.

Offline-capable behavior includes:

- Viewing local tasks
- Completing and snoozing tasks
- Playing the memory game
- Changing settings
- Saving recorded audio locally
- Saving local diary notes
- Viewing local reports

Gemini transcription requires network access. If transcription fails, the
recording is kept locally and the app displays an offline message.

Automatic server synchronization is not implemented yet.


P - PERMISSIONS
---------------
The app may request:

- Microphone permission for Voice Diary
- Notification permission for local alarms
- Foreground location permission for the home boundary
- Background location permission for future safety monitoring

Permission denial should not be treated as an emergency failure.
The current app shows a recovery message or opens phone settings when
appropriate.

S - SECURITY AND PRIVACY
------------------------
Important security rules:

- Never place GEMINI_API_KEY inside the mobile application.
- The Gemini key belongs on the API server as a server environment secret.
- Never paste API keys or credentials into source code.
- Do not use the fake test profile as real medical data.
- Do not publish the sample caregiver phone number as a real contact.
- Production patient records require authentication and access controls.

The current API server does not yet provide full patient authentication or
caregiver authorization.


T - TEST DATA DELETE PROCESS
----------------------------
To delete the fake profile:

1. Open More.
2. Scroll to Test patient database.
3. Confirm that the card says:

       TEST DATA — DELETE ME

4. Tap Delete test data.
5. Confirm the destructive prompt.

The delete action removes the test profile, test tasks, test notifications,
test diary notes, and test game progress from local storage.

To restore the test process:

1. Return to More.
2. Open Test patient database.
3. Tap Reload test data.

The delete and reload actions are separate from any future Supabase
database and do not delete remote production records.

V - VOICE DIARY
---------------
Voice Diary works as follows:

1. Open the Voice tab.
2. Tap Start a voice note.
3. Approve microphone permission.
4. Speak naturally.
5. Tap Stop.
6. The audio file is saved locally.
7. The app sends a base64 copy to the API when online.
8. Gemini returns a transcript and possible task.
9. The transcript is saved with the local audio reference.
10. A possible task is displayed for patient confirmation.
11. Tap Add to create the reminder.

If the API or network is unavailable, the app keeps the audio locally and
saves an offline note.
